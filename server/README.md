# exbotweb — Telegram-бот (server)

Telegram-бот українською для особистого обліку витрат. Працює в приватних чатах через long polling. Дані зберігаються в PostgreSQL і залишаються після перезапуску. React-основа сайту розташована в корені репозиторію. Ця папка містить серверну частину з Telegram-ботом; HTTP API для React ще не реалізовано.

## Можливості

- Профіль за числовим Telegram ID; username не використовується для доступу до даних.
- Додавання витрат повідомленням або покроково через `/add`.
- Цілі найменші одиниці валюти (`bigint` у TypeScript, `BIGINT` у PostgreSQL). Жодних обчислень грошей через JavaScript float.
- Початкова валюта UAH і дата за часовим поясом `Europe/Kyiv`; налаштовуються через середовище. Зміна валюти користувачем впливає лише на нові записи.
- Початкові категорії: Їжа, Транспорт, Дім, Ігри, Здоров’я, Покупки, Інше. Визначення за ключовими словами, кнопки для невідомих або неоднозначних категорій.
- Власні категорії, перейменування, архівування з підтвердженням. Повторне додавання назви відновлює архівовану категорію. Перейменування змінює назву також в історичних звітах.
- Витрати за день із пагінацією, підсумки за місяць, останні 10 записів, видалення останнього запису з підтвердженням.
- `/checkcategory`: вибір категорії кнопкою, суми й кількість записів за поточний місяць та за весь час. Архівовані категорії теж доступні; довгі списки розбиті на сторінки.
- Справжній `.xlsx` у Telegram: дата, опис, категорія, сума, валюта. Внизу того самого аркуша — підсумки за категоріями та загальна сума за місяць експорту, окремо для кожної валюти. Дати й звичайні суми мають відповідні типи; текст користувача не перетворюється на формули. Усі суми обчислюються через `bigint`. Надвеликі підсумки понад 15 значущих цифр з урахуванням копійок записуються текстом, щоб не втрачати точність Excel.
- Незавершені покрокові діалоги зберігаються в БД на 24 години. Будь-яка команда скасовує попередню незавершену дію.
- Захист від повторного запису одного Telegram update і від застарілих підтверджень. У групових чатах бот лише пропонує перейти в особистий чат.

Валюти першої версії: `UAH`, `USD`, `EUR`, `PLN`, `GBP`, `CZK`, `CAD`, `CHF` (усі мають дві десяткові позиції). Конвертації немає: кожна валюта має окремий підсумок. Сума — від `0,01` до `999999999,99`, опис — до 300 символів, назва категорії — до 40. До 30 активних категорій на користувача; останню активну категорію архівувати не можна. Експорт обмежений 50 000 записами на місяць; при перевищенні бот повідомляє про ліміт.

## Команди

| Команда | Дія |
| --- | --- |
| `/start` | Створити профіль за потреби, привітання і меню |
| `/help` | Інструкція та приклади |
| `/add` | Запит опису, потім суми, за потреби категорії |
| `/add кава 85,50` | Додати одним рядком |
| `/today` | Витрати за сьогодні, по 10 на сторінку, і повний підсумок дня |
| `/month` | Підсумок поточного місяця за категоріями та валютами |
| `/last` | Останні 10 внесених витрат |
| `/undo` | Запропонувати видалення останньої внесеної витрати; виконати лише після натискання кнопки |
| `/categories` | Додати, перейменувати, архівувати категорії |
| `/checkcategory` | Обрати категорію кнопкою та переглянути витрати за поточний місяць і весь час, окремо за валютами |
| `/currency` | Показати поточну валюту й кнопки вибору |
| `/currency USD` | Змінити валюту для наступних витрат |
| `/export` | Excel за поточний місяць |
| `/export 2026-10` | Excel за конкретний місяць у форматі `YYYY-MM` (рік 1900–9998) |
| `/cancel` | Скасувати поточну незавершену дію |

Приклади звичайних повідомлень:

```text
ігри 500
кава 85,50
500 ігри
таксі 120.25
```

Сума має бути на початку або в кінці, без пробілів усередині. Повідомлення `2 кави 100`, `кава 100 200` або `кава 100 грн` бот не зберігає, бо не може однозначно розібрати їх. Для опису з числами використайте `/add`: окремо введіть `2 кави`, потім `100`.

## Що встановити

- **Node.js 24 LTS, версія 24.11 або новіша в гілці 24**, та npm.
- **Windows x64:** локальна база через `npm run db:local` без Docker. Альтернатива — Docker Desktop із Docker Compose або власний PostgreSQL. Compose використовує PostgreSQL 17 і відкриває порт лише на `127.0.0.1`.
- Telegram і власний токен бота.

Стек: TypeScript, grammY, Prisma 7 з PostgreSQL-адаптером, ExcelJS. Версії зафіксовано в `package-lock.json`; для відтворюваного встановлення використовуйте `npm ci`.

## Токен від BotFather

1. Відкрийте офіційного [@BotFather](https://t.me/BotFather) у Telegram.
2. Надішліть `/newbot`, задайте назву та унікальний username, що закінчується на `bot`.
3. Скопіюйте отриманий токен у `BOT_TOKEN` локального `.env`.
4. Відкрийте створеного бота в приватному чаті. Надішліть `/start` після запуску застосунку.

Токен не потрібен для автоматичних тестів. Для справжньої роботи використовуйте лише власний токен; вигаданих реквізитів у конфігурації немає.

## PostgreSQL без Docker (Windows)

Для локальної розробки на Windows x64 виконайте з папки `server/`:

```powershell
npm ci
npm run db:local
```

Команда створює PostgreSQL 17 у фоні, базу та таблиці, генерує пароль і заповнює `DATABASE_URL`. За відсутності `.env` він створюється з шаблону. Наявний токен зберігається; підключення до іншої бази не замінюється. Заповніть `BOT_TOKEN` у `.env`, якщо він ще порожній, потім:

```powershell
npm run db:generate
npm run dev
```

Стан: `npm run db:local:status`. Зупинка: `npm run db:local:stop`. Повторний запуск: `npm run db:local`. Після перезавантаження Windows також потрібна команда запуску; системна служба не встановлюється.

Дані зберігаються в `server/.postgres/data/`, журнал — у `server/.postgres/postgres.log`. Ця папка виключена з Git. Не видаляйте її або згенерований пароль без резервної копії. База слухає лише `127.0.0.1`, порт `5432` (або `POSTGRES_PORT`, заданий перед першою ініціалізацією).

Команди `db:local*` керують цією локальною базою; `db:up`, `db:stop` і `db:down` нижче призначені для Docker. Для серверного розгортання використовуйте звичайний PostgreSQL або Docker.

## Локальний запуск із Docker або власною базою

Відкрийте термінал у папці `server/`. Усі команди нижче виконуються з цієї папки; скорочені команди з кореня наведено в `../README.md`.

```powershell
npm ci
Copy-Item .env.example .env
```

У Linux/macOS замість `Copy-Item` виконайте `cp .env.example .env`. Якщо `.env` уже існує, відредагуйте його, не копіюйте поверх.

Заповніть `.env`:

| Змінна | Значення |
| --- | --- |
| `BOT_TOKEN` | Справжній токен від BotFather |
| `DATABASE_URL` | URL вашої бази PostgreSQL |
| `DEFAULT_CURRENCY` | `UAH` — початкова валюта лише для нових профілів |
| `TIME_ZONE` | `Europe/Kyiv` — часовий пояс для календарної дати й звітів |
| `NODE_ENV` | `development` локально, `production` на сервері |
| `POSTGRES_USER` | `expensebot` для Compose |
| `POSTGRES_DB` | `expensebot` для Compose |
| `POSTGRES_PASSWORD` | Власний непорожній пароль PostgreSQL |
| `POSTGRES_PORT` | `5432` або інший вільний порт для Compose |

Формат URL для локального Compose:

```text
postgresql://expensebot:<URL-encoded-пароль>@127.0.0.1:5432/expensebot
```

Замініть `<URL-encoded-пароль>` на власний пароль із `POSTGRES_PASSWORD`, закодувавши спеціальні символи для URL. Дужки не є частиною пароля. Якщо змінюєте користувача, назву бази чи порт, змініть відповідні частини URL. Для власного PostgreSQL потрібні лише перші п’ять змінних; Compose-змінні не використовуються застосунком.

Запустіть Docker Desktop, потім:

```powershell
npm run db:up
npm run db:generate
npm run db:deploy
npm run dev
```

`db:up` чекає на готовність PostgreSQL. `db:deploy` застосовує наявні міграції до вказаної в `DATABASE_URL` бази. Профіль і сім початкових категорій створюються атомарно при першому приватному зверненні користувача, тому окрема команда seed не потрібна. Повторний `/start` не дублює категорії і не повертає архівовані.

Перед обробкою повідомлень бот перевіряє підключення і наявність таблиці користувачів, реєструє меню команд у Telegram, потім запускає polling. Очікуване повідомлення термінала: `Бот запущено (long polling)`.

Для запуску зібраного коду:

```powershell
npm run build
npm start
```

Для зупинки бота натисніть **Ctrl+C** у його терміналі. Бот завершує поточну обробку й закриває підключення до БД. Для бази:

```powershell
npm run db:stop
```

Або видаліть контейнери, зберігши іменований том із даними:

```powershell
npm run db:down
```

Не додавайте `-v` до `docker compose down`, якщо хочете зберегти базу. Зміна `POSTGRES_PASSWORD` у `.env` не змінює пароль у вже створеному томі — його потрібно окремо змінити в PostgreSQL. Не видаляйте том для виправлення пароля без резервної копії.

## Ручна перевірка

1. `/start`: отримайте привітання, меню та валюту UAH. Повторіть — категорій має залишитися сім.
2. Надішліть `ігри 500`, `кава 85,50`, `500 ігри`. Переконайтеся, що суми та категорії правильні. Для `подарунок 300` оберіть категорію кнопкою; до вибору запису в `/last` бути не повинно (команда скасовує незавершений вибір).
3. Перевірте `/add`: опис `2 кави`, неправильна сума `-100`, потім `100`. Неправильна сума не має завершувати діалог чи створювати запис.
4. `/today`: перевірте список і повний підсумок. `/month`: перевірте категорії й підсумок місяця.
5. `/currency USD`, потім `ігри 10`: старі записи мають залишитися UAH, звіт має показувати UAH та USD окремо. Поверніть `/currency UAH`.
6. `/undo`: спочатку скасуйте, перевірте `/last`. Повторіть `/undo`, підтвердьте — видалитися має лише показаний запис. Повторне натискання старої кнопки не повинно видаляти наступний запис.
7. `/categories`: додайте категорію, перейменуйте й архівуйте її. Старі витрати повинні залишатися у звітах. Через `/checkcategory` оберіть категорію та перевірте суми за місяць і весь час. Перевірте також порожню й архівовану категорії та повернення до списку кнопкою.
8. `/export`: завантажте файл та відкрийте його в Excel/LibreOffice. Перевірте п’ять колонок, числові суми та дати. Звірте нижній блок підсумків за категоріями та загальні суми за кожною валютою із записами цього місяця. `/export YYYY-MM` для порожнього місяця має повернути пояснення без файла.
9. Зупиніть і знову запустіть бота: витрати мають залишитися. Перевірте продовження `/add` після перезапуску.
10. Другий Telegram-користувач повинен бачити лише свої дані. У групі бот має пропонувати приватний чат.

## Автоматичні перевірки й розробка

```powershell
npm run db:generate
npm run db:validate
npm run typecheck
npm test
npm run build
```

`npm test` перевіряє розбір повідомлень, точні суми, категорії, часові пояси, межі місяців, конфігурацію та повторне відкриття сформованого XLSX. `npm run test:watch` запускає ці перевірки в режимі спостереження.

Інтеграційні тести потребують **окремої** PostgreSQL-бази, назва якої закінчується на `_test`. Вони використовують справжню Prisma та PostgreSQL, але перехоплюють усі Telegram API-запити без доступу до Telegram. Створюють випадкових користувачів і видаляють лише власні тестові записи.

Приклад для локального Compose у PowerShell (у URL підставте власний пароль):

```powershell
docker compose exec db createdb -U expensebot expensebot_test
$env:TEST_DATABASE_URL = 'postgresql://expensebot:<URL-encoded-пароль>@127.0.0.1:5432/expensebot_test'
$previousDatabaseUrl = $env:DATABASE_URL
try {
  $env:DATABASE_URL = $env:TEST_DATABASE_URL
  npm run db:deploy
  npm run test:integration
} finally {
  $env:DATABASE_URL = $previousDatabaseUrl
  Remove-Item Env:TEST_DATABASE_URL
}
```

Не використовуйте для цього робочу базу. Якщо тестова база вже існує, пропустіть `createdb`. Набір перевіряє команди, підтвердження, чужі категорії та витрати, цілісність FK, повторну доставку update, відновлення діалогу, звіти, експорт і перепідключення.

Після зміни Prisma-схеми в розробці:

```powershell
npm run db:migrate -- --name describe_change
npm run db:generate
```

`db:migrate` може потребувати права створення shadow database; використовуйте його лише на базі розробки. Для готових міграцій і сервера застосовуйте `db:deploy`. Додатково: `npm run db:status` показує стан міграцій, `npm run db:studio` відкриває Prisma Studio. Studio має доступ до даних усіх користувачів — запускайте його лише локально для адміністратора.

## Постійний запуск на сервері

Потрібен VPS або інший сервер із постійним Node.js-процесом, доступом до PostgreSQL та вихідним HTTPS до Telegram. Для long polling публічний HTTP-порт і webhook не потрібні. Запускайте **одну копію на один BOT_TOKEN**.

1. Встановіть Node.js 24 LTS, скопіюйте репозиторій, перейдіть у `server/` і створіть там `.env` з `NODE_ENV=production`, власним токеном та URL серверної бази. Для віддаленої БД налаштуйте TLS згідно з вимогами її провайдера.
2. Виконайте `npm ci`, `npm run db:generate`, `npm run db:deploy`, `npm run build`. Залежності розробки потрібні на етапі збірки та міграцій.
3. Налаштуйте менеджер процесів. Приклад Linux systemd є в `deploy/expensebot.service`. Укажіть реального непривілейованого користувача, шлях до проєкту й абсолютний шлях до `node` (`command -v node`). Приклад передбачає користувача `expensebot` і каталог `/opt/exbotweb/server`.
4. Збережіть налаштований unit як `/etc/systemd/system/expensebot.service`, обмежте доступ до `.env` власником процесу (`chmod 600 /opt/exbotweb/server/.env`), потім:

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now expensebot
sudo systemctl status expensebot
journalctl -u expensebot -f
```

Зупинка: `sudo systemctl stop expensebot`. Після оновлення залежностей, міграцій і збірки: `sudo systemctl restart expensebot`. Перед запуском серверної копії зупиніть локальну з тим самим токеном. Налаштуйте регулярні резервні копії PostgreSQL і перевіряйте їх відновлення.

## Поширені проблеми

- **Неправильний токен / 401.** Перевірте `BOT_TOKEN`, зайві пробіли, актуальність токена в BotFather. Якщо токен оприлюднено, відкличте його через BotFather та замініть у середовищі.
- **База недоступна.** Перевірте Docker Desktop, `docker compose ps`, `DATABASE_URL`, пароль і порт. `localhost` із контейнера означає сам контейнер; цей Compose розрахований на запуск Node.js на хості. Переконайтеся, що виконано `npm run db:deploy`.
- **Немає Prisma Client.** Виконайте `npm run db:generate` після `npm ci` або змін схеми.
- **Конфлікт 409.** Зупиніть інші локальні чи серверні копії бота з тим самим токеном. Не запускайте `npm run dev` і `npm start` одночасно. grammY під час запуску polling прибирає попередній webhook без відкидання накопичених update.
- **Проблема Telegram або мережі.** Перевірте вихідне HTTPS-з’єднання. Бот обробляє помилки окремих дій; якщо відповідь не дійшла після запису, перевірте `/last` перед ручним повторним додаванням.
- **Застаріла кнопка.** Виконайте відповідну команду ще раз. Кнопка прив’язана до поточної дії та не підтверджує інший запис.
- **Несподівана дата.** Перевірте `TIME_ZONE` і системний годинник. Дата витрати визначається при введенні суми, у звітах використовується календарна дата без перерахунку за UTC. Зміна часового поясу не переписує попередні дати.

Не публікуйте `.env`, токен бота або пароль бази. `.env` виключено через `.gitignore`; `.env.example` навмисно не містить секретів. Код не логує тексти витрат, Telegram payload, рядки підключення або сирі stack trace. Видалення через `/undo` фізично видаляє конкретну витрату. Залишається лише технічний ключ операції та час видалення без опису, суми чи категорії: повторна доставка старого повідомлення не відновить видалений запис. Архівування категорії її витрат не видаляє.

## Структура та наступний етап

```text
src/domain/       точні суми, дати, парсер і категорії без Telegram/БД
src/services/     операції обліку, звіти та XLSX-експорт
src/db/           Prisma + PostgreSQL adapter
src/bot/          Telegram-обробники, помилки, збереження діалогів
src/main.ts       запуск, перевірка БД, graceful shutdown
prisma/           схема і SQL-міграції з обмеженнями цілісності
tests/            автономні та інтеграційні перевірки
deploy/           приклад systemd unit
```

Операції сервісу завжди отримують ID власника; запити фільтрують дані за ним. Складений зовнішній ключ у PostgreSQL додатково забороняє витраті посилатися на категорію іншого користувача. Сім категорій створюються разом із профілем, окремого спільного списку категорій немає.

Наступний етап: HTTP API над сервісом обліку, справжня перевірка особи для вебдоступу та React-інтерфейс; за потреби — редагування витрат і вибір дат. Для ширшого використання варто додати моніторинг, політику видалення профілю й пагінацію великих експортів. Спільні витрати, поділ рахунків, OCR, Pro-підписка, платежі та Splitwise у цій версії не реалізовані.

Технічні джерела: [Prisma 7 та driver adapters](https://docs.prisma.io/docs/guides/upgrade-prisma-orm/v7), [grammY: long polling](https://grammy.dev/guide/deployment-types.html), [ExcelJS](https://github.com/exceljs/exceljs).
